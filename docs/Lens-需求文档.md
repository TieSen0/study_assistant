# Lens 个人论文阅读工作台：需求文档

## 1. 项目定义

Lens 是一个以 **“读原论文 / 原书籍”** 为中心的个人阅读工作台。

它不是把 PDF 转成排版混乱的网页，不是刷题打卡工具，也不是聊天机器人套壳。它的核心任务是：让用户在笔记本电脑上高效、舒适地阅读原始资料；需要时，在原文准确位置留下批注、问题、存疑和书签，并为未来的 AI 辅助保留可靠上下文。

### 核心原则

1. **原件优先**：用户看到的永远是原 PDF，保留字体、公式、图片、表格、双栏和页码。
2. **提取黑盒化**：文本提取、OCR、结构识别只服务检索和 AI，不替代阅读正文。
3. **Office 式阅读优先**：阅读器交互以 WPS / Office 的 PDF 阅读模式为基准；先把熟悉、完整的阅读、检索、视图和批注工作流做好，再叠加 AI。
4. **锚定原文**：所有批注、问题、存疑、书签都必须定位到原文页码与区域，缩放后仍准确。
5. **先数据、后智能**：先完成稳定的资料与标记 CRUD，再接入复杂 AI、RAG 或多模态能力。

---

## 2. 用户与主要场景

### 目标用户

- 用户本人，主要在笔记本电脑阅读论文、教材、技术书籍和其他 PDF 资料。
- 有时阅读普通文字论文，有时阅读公式、图表、扫描件较多的资料。

### 主场景

1. 导入一篇 PDF，尽快开始读第一页。
2. 像在 WPS / Office 一样进入阅读模式：调整缩放与页面视图，翻页、连续滚动、查找和回到上次阅读位置。
3. 划选文字、公式、图片或表格，添加批注、提问、存疑、书签，并在批注管理中回访。
4. 从“存疑队列”或书签回到某个具体原文区域，并将其标记为已解决。
5. 必要时查看后台实际提取的内容，确认 AI 未来会读到什么。
6. 后续让 AI 结合选区、页内上下文和全文资料回答问题。

## 3. 当前已实现

### 资料库

- 上传 PDF、TXT、Markdown；原文件保存于私有资料库。
- 资料列表展示与打开。
- 资料重命名、删除。
- 删除资料时同时删除关联页文本、批注、存疑、书签和原文件。

### 原文与解析

- PDF 原文件保留。
- 普通模式尝试提取每页文字，作为后台索引。
- Debug 面板可查看当前页提取文本与无文字层状态。
- 扫描页即使没有文字层，也应允许保存和原样阅读。

### 标记数据

- 框选区域可创建：批注、询问、存疑、书签。
- 标记按文档、页码、归一化区域坐标保存。
- 存疑队列可跳转回原页，并支持已解决 / 未解决状态。
- 标记支持编辑与删除。

### 已知限制

- 当前“询问”仅打开问答界面并绑定选区，尚未真正接入大模型回答。
- 当前标记模式使用前端 PDF 画布，打开速度不如原生 PDF 阅读器。
- 当前原生快速阅读和标记模式仍需要进一步整合。
- 当前尚未形成完整的 WPS / Office 式阅读模式：目录 / 缩略图、视图切换、查找范围、批注工具箱与批注管理仍待完成。

## 4. 需求优先级

### P0：WPS / Office 式阅读模式（当前最高优先级）

目标：不再设计一套“类阅读器”的简化交互，而是先复刻桌面端 WPS / Office 对 PDF / 论文的核心阅读工作流。Lens 的 AI 功能只能作为这个工作流中的工具，不得取代它。

#### P0.1 阅读模式框架

- [ ] 从资料库打开文档后，进入专用的“阅读模式”；提供明确的“退出阅读模式”，返回资料库而不丢失进度。
- [ ] 顶部采用 Office 风格功能区：`文件 / 视图 / 批注 / 翻译 / 查找`，功能按需展开，不将操作堆在正文上。
- [ ] 阅读区可占满浏览器可用空间；“适合宽度”时论文页面横向尽可能铺满，保留合理页边距；“适合整页”保证完整页面可见。
- [ ] 大 PDF 支持分段读取，尽快显示第一页；默认原生 PDF 快速阅读，不默认加载交互画布。
- [ ] 记住每篇资料最后阅读页、缩放和视图方式，下次打开直接恢复。

#### P0.2 视图与导航（对应 WPS「视图」）

- [ ] 缩放：减小 / 放大、预设百分比、输入百分比、适合宽度、适合整页；`Ctrl + 滚轮` 缩放且不丢失当前位置。
- [ ] 页面布局：单页、双页、连续单页、连续双页；双页模式正确处理封面页与奇偶页。
- [ ] 页码导航：上一页、下一页、页码输入跳转、方向键翻页 / 滚动。
- [ ] 左侧导航栏：页缩略图、PDF 目录（文档有目录时）、书签三个标签；可收起。
- [ ] 显示阅读进度、当前页 / 总页数；“返回上次位置”。

#### P0.3 查找（对应 WPS「查找」）

- [ ] 文档内全文搜索，结果列表按页码展示并可跳转、定位和高亮。
- [ ] 查找选项：整词匹配、区分大小写。
- [ ] 可选择搜索范围：原文全文、书签标题与内容、批注内容；默认仅搜索原文全文。
- [ ] 搜索依赖后台文本索引；无文字层或索引未就绪时必须明确提示，不能伪造结果。

#### P0.4 批注、书签与批注管理（对应 WPS「批注」）

- [ ] 支持高亮、下划线、删除线、手写 / 绘制、文本框、便签注释、矩形框选、书签。
- [ ] 文字可精确划选；公式、图片、表格可矩形框选；标记始终锚定在原 PDF 页与相对坐标。
- [ ] “批注工具箱”集中展示工具、颜色、撤销 / 重做、显示 / 隐藏批注，避免正文中出现持久的大型操作面板。
- [ ] “批注管理”侧栏按页码、类型、时间筛选和跳转；支持编辑、删除、导出。
- [ ] 书签可创建、重命名、删除、分组（后续）并在左侧书签标签中跳转。
- [ ] “存疑”是可筛选的批注状态；存疑队列是批注管理的一个视图，支持待处理 / 已解决。

#### P0.5 翻译与 AI 扩展位（先做交互，不伪装模型能力）

- [ ] 划词后出现紧凑浮动工具条：翻译、批注、询问、存疑、书签。
- [ ] 翻译面板支持原文片段、翻译结果、复制与替换 / 对照显示；未配置翻译服务时明确显示“需接入服务”。
- [ ] 划词翻译和图表 / 选区翻译复用同一个选区锚点。
- [ ] “询问 AI”带入选区、当前页、页内上下文和全文索引；在没有模型后端前仅保留可见接口位和配置提示。

**验收标准**：导入 20–50 页论文后能尽快开始看第一页；公式、图表、双栏和字体与原 PDF 一致。用户可以不学习 Lens 的新规则，而凭 WPS / Office 使用习惯完成：调整到占满宽度的视图、切换单双页和连续阅读、查找、加书签与批注、在批注管理中回访、退出阅读模式。所有用户标记和阅读位置在刷新后仍可恢复。

### P1：资料 CRUD、体验打磨与导出

目标：将用户阅读动作可靠地保存到原文位置。

- [x] 资料上传、查看、重命名、删除。
- [x] 标记创建、读取、编辑、状态更新、删除。
- [x] 批注、询问、存疑、书签四种标记类型。
- [x] 存疑队列跳转与解决状态。
- [ ] 导入进度、失败重试、批量导入。
- [ ] 文档文件夹、标签、排序、归档。
- [ ] 导出批注与存疑列表（Markdown / PDF 附录）。
- [ ] 阅读器快捷键、无障碍、触控板手势和视觉细节打磨。

### P2：后台提取、检索与 Debug

目标：为 AI 建立可靠上下文，但不污染用户阅读体验。

- [x] 每页普通文字提取与 Debug 查看。
- [ ] 将全文拆成后台 Block：标题、段落、图、表、公式、图注。
- [ ] Block 保存页码、区域坐标、阅读顺序、提取来源、置信度。
- [ ] 普通模式：优先使用 PDF 原生文字层，不额外消耗模型资源。
- [ ] 增强模式：对扫描件、公式密集、复杂图表页进行 OCR / 多模态识别。
- [ ] 普通与增强结果可在 Debug 中对照。
- [ ] 全文检索索引；支持选区附近上下文和跨页引用检索。

### P3：AI 阅读辅助

目标：AI 是基于证据的阅读助手，而不是脱离原文的聊天框。

- [ ] 询问标记自动打开侧边栏，并绑定选区、页码、页内上下文。
- [ ] 每次问题都可从全文检索相关定义、方法、实验和结论。
- [ ] 回答必须展示引用页码和原文区域。
- [ ] 图表 / 表格问题可带选区截图与图注进入增强识别。
- [ ] 对话与对应标记绑定，方便回看。
- [ ] “解释 / 拆解论证 / 标出术语 / 变式追问”等阅读操作。

**约束**：ChatGPT Plus 不是网站后端 API。自动大模型功能需要另接 API、可用本地模型，或明确的手动工作流；在此之前 UI 只保留接口位，不伪装成已具备 AI 回答能力。

### P4：后续扩展（暂不做）

- EPUB、Word、网页文章等更多格式。
- 多文档知识库、跨论文关联图谱。
- 协作、分享、多账号。
- 自动生成长笔记、打卡、任务系统。
- 考研题库、错题本、ComfyUI、数据集管理等旧方向。

这些能力与当前“个人论文阅读”主线不同，除非重新立项，否则不进入近期开发。

## 5. 数据边界与建议模型

### 用户可见的事实数据

```text
Document
├─ 原始文件（R2）
├─ 标题、类型、页数、导入时间
├─ 最后阅读页、最近打开时间
└─ Page
   ├─ 页码、尺寸、旋转
   └─ Annotation
      ├─ 类型：note / question / doubt / bookmark
      ├─ 锚点：页码 + 一个或多个归一化矩形坐标
      ├─ 内容、颜色、状态、时间
      └─ 对话引用（未来）
```

### 仅给系统 / AI 使用的索引数据

```text
ExtractionRun
├─ 模式：normal / enhanced
├─ 版本、状态、耗时、错误
└─ Block
   ├─ 类型：heading / paragraph / figure / table / equation / caption
   ├─ 原始提取文本与规范化文本
   ├─ 页码、区域、阅读顺序
   ├─ 提取来源与置信度
   └─ 检索向量或关键词索引（未来）
```

### 数据约束

- 原始 PDF 不被修改或替换。
- 用户标记锚点使用相对坐标，不能依赖固定像素。
- 后台解析可以重跑、可保留多个版本；不能覆盖或损坏用户标记。
- 删除资料必须级联删除关联的结构化数据与原文件。
- AI 输出必须存引用锚点，不可只有无来源的文本结论。

---

## 6. 明确不做什么

- 不把解析文本当成用户阅读正文。
- 不为了“学习感”强制用户写长笔记、打卡或分类。
- 不在未接入模型时假装可以生成真实 AI 回答。
- 不默认把所有页面都发送给多模态模型。
- 不让复杂标记能力拖慢最基础的打开和阅读体验。

---

## 7. 下一阶段执行顺序

1. 完成 P0 阅读模式骨架与视图：原生快速阅读、缩放、单双页 / 连续、进度恢复、目录 / 缩略图 / 书签。
2. 完成 P0 查找与批注工作流：全文检索、划词、批注工具箱、批注管理、存疑队列、翻译 / AI 接口位。
3. 做 P2：后台 Block 数据模型、普通 / 增强识别、Debug 对照、全文检索索引。
4. 打磨 P1 的资料管理、导出和阅读器细节。
5. 最后才接 P3：基于选区和全文证据的 AI 问答。

任何新功能先问一个问题：**它会让“打开并读好一篇原论文”更快、更清楚，还是只是显得更复杂？**
